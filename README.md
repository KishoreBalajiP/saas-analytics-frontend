# SaaS Analytics — Frontend

React + TypeScript + TanStack Start frontend for the SaaS Analytics Platform.

## Commands

```sh
npm install
npm run dev          # vite dev (TanStack Start)
npm run build        # vite build → Vercel-shaped .vercel/output
npm run start        # vite preview (local production preview)
npm run test         # vitest run (jsdom, 12 test files / 207 tests)
npm run test:watch   # vitest
npm run typecheck    # tsc --noEmit
npm run lint         # eslint .
npm run format       # prettier --write .
```

## Source layout

```
src/
  components/         # shared UI primitives (ui/, layout/, common/)
  features/           # feature-scoped: api/ + components/ + (optional hooks/)
    auth/             # shared auth API (login, refresh, MFA, profile)
    datasets/         # tenant: connectors + their detail views
    analytics/        # tenant: query builder, history, results
    dashboards/       # tenant: placeholder for Phase 3
    reports/          # tenant: placeholder for Phase 3
    alerts/           # tenant: placeholder for Phase 3
    notifications/    # tenant: placeholder for Phase 3
    api-keys/         # tenant: placeholder for Phase 3
    embed/            # tenant: placeholder for Phase 3
    admin/            # admin: tenants, admins, roles, audit, compliance, support, monitoring
  lib/
    api/              # shared HTTP client + types (client.ts, types.ts)
    auth/             # TenantSessionProvider / AdminSessionProvider
    errors/           # error-capture, error-page, lovable-error-reporting
    permissions/      # Permissions enum + has/hasAny/hasAll helpers
    utils/            # cn(), general utilities
  hooks/              # cross-feature hooks
  routes/             # TanStack Start file-based routes
  test/               # vitest setup
  router.tsx          # createRouter()
  routeTree.gen.ts    # auto-generated by TanStack Router (do not edit)
  server.ts           # SSR error wrapper entry
  start.ts            # createStart() with error + CSRF middleware
  styles.css          # Tailwind v4 + design tokens
```

See `src/features/README.md` for feature conventions, `VERCEL.md` for deployment.

## Environment

`.env.example` documents the placeholders. Copy it to `.env` for local development:

```sh
cp .env.example .env
```

`.env.test` is read by Vitest and pins the dev backend URL. `.env` (gitignored)
holds the production URL when deploying.

## Backend contract

The backend is the source of truth. Always consult
`src/docs/backend/frontend-api-contract.md` and the master prompt before
introducing new endpoints, response fields, or permissions.

## Original task
